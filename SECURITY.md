# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Until a private
reporting channel is published, contact the repository owner directly and
include reproduction steps, potential impact, and any suggested mitigation.

## Development expectations

- Never commit credentials, tokens, private keys, or production data.
- Use least-privilege access for external services.
- Validate untrusted input at system boundaries.
- Keep dependencies reviewed and updated once a package ecosystem is selected.
- Document any collection, retention, or sharing of user data before shipping.
